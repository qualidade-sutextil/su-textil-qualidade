Inspeção de Costura (recebimento)

Registro padronizado da inspeção de lotes recebidos, com rastreabilidade, amostragem, resultado e evidências.

Como lançar: preencha os dados do romaneio uma vez, adicione cada tamanho (quantidade inspecionada, quantidade reprovada, problema e foto) e, quando terminar, clique em Finalizar romaneio para gerar um único relatório. O que você digitar fica salvo como rascunho, mesmo se fechar a página.
Critério de inspeção: registre o lote recebido, a quantidade inspecionada, as não conformidades encontradas e o resultado. A taxa de amostragem é calculada automaticamente quando possível. O registro deve permitir rastrear fornecedor/oficina, cliente, pedido, produto, problema e evidência.

Fluxos dos Processos

Monte um fluxograma real com etapas conectadas. Cada etapa possui destino; decisões exigem um destino diferente ou igual para SIM e NÃO. As setas são geradas a partir das conexões configuradas.

Como montar: 1) adicione o início e as atividades; 2) adicione as etapas que devem acontecer em cada caminho; 3) em cada etapa, escolha o próximo destino nas listas suspensas. Em uma decisão, configure separadamente o destino do SIM e do NÃO. 4) confira o mapa e resolva os avisos antes de salvar. Você pode criar vários finais e reunir caminhos na mesma etapa.

Comentários e solicitações da Diretoria


A Diretoria pode registrar dúvidas, solicitações e comentários; a Qualidade poderá consultar, responder e marcar o tratamento. Requer a tabela compartilhada descrita no final desta seção.














 




SQL para habilitar comentários compartilhados (executar uma vez no Supabase → SQL Editor)
Confira que a tabela user_roles usa user_id e role, como configurado no acesso atual.
create table if not exists public.director_comments (
  id uuid primary key default gen_random_uuid(),
  subject text not null,
  body text not null,
  priority text not null default 'Normal',
  related_area text not null default 'Geral',
  status text not null default 'Aberto',
  author_name text,
  author_role text,
  response text,
  responded_at timestamptz,
  responded_by text,
  created_at timestamptz not null default now()
);
alter table public.director_comments enable row level security;
create policy "authorized users read director comments"
on public.director_comments for select to authenticated
using (exists (select 1 from public.user_roles ur
  where ur.user_id = auth.uid() and ur.role in ('quality','director')));
create policy "directors can create comments"
on public.director_comments for insert to authenticated
with check (exists (select 1 from public.user_roles ur
  where ur.user_id = auth.uid() and ur.role = 'director'));
create policy "quality can respond to comments"
on public.director_comments for update to authenticated
using (exists (select 1 from public.user_roles ur
  where ur.user_id = auth.uid() and ur.role = 'quality'))
with check (exists (select 1 from public.user_roles ur
  where ur.user_id = auth.uid() and ur.role = 'quality'));
Se a tabela user_roles tiver nomes de colunas diferentes, ajuste o SQL antes de executar. Não desative RLS.
